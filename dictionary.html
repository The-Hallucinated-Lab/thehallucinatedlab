Dictionary

The vocabulary this site runs on, defined in plain English — what each term means, and when it actually matters.

Two sections. Artificial Intelligence covers the words that appear on the tool pages — tokens, embeddings, retrieval, quantisation. Software Engineering covers the words that appear in how this site is built and reviewed. Every entry is short on purpose: the definition, then the part that is easy to get wrong.

Artificial Intelligence Software Engineering

Artificial Intelligence

Eighteen terms, in alphabetical order. These are the ones used on the Tools, Pipelines and Assistant pages without stopping to explain them.

Agent
A model given tools and a loop: it picks a tool, reads the result, and decides again, rather than answering in one pass. The loop is what makes it an agent — the model underneath is the same model.
Attention
The mechanism that lets a model weigh every token against every other token when deciding what a token means in context. It is also why long prompts are expensive: the work grows with the square of the sequence length.
Chunking
Splitting a long document into retrieval-sized pieces. Where you cut decides what can be retrieved — a chunk cut through the middle of an argument can only ever return half of it, which is why splitting on headings beats splitting on character counts.
Context window
The maximum number of tokens a model can hold at once, prompt and answer together. Anything past the limit is dropped, usually without a warning, which is why oversized inputs fail in ways that look like the model forgetting rather than the tool truncating.
Distillation
Training a small model to imitate a larger one's outputs. You get most of the behaviour at a fraction of the running cost, and you inherit the teacher's habits — including the wrong ones.
Embedding
A list of numbers that represents a piece of text so that similar meanings sit near each other. Retrieval is then a distance measurement in that space and nothing more, which is both why it is fast and why it returns confidently irrelevant results when the space is a poor fit for your documents.
Fine-tuning
Continuing a model's training on your own examples so it adopts a behaviour, a tone, or an output format. It teaches shape reliably. It is a poor and expensive way to teach facts — that is what retrieval is for.
Hallucination
A fluent, confident, wrong answer. Not a malfunction in the ordinary sense: the model is predicting plausible text, and plausible is not the same thing as true. Grounding, citation and verification reduce it; nothing removes it.
Inference
Running a trained model to get an answer, as opposed to training one. Everything on this site described as running "locally" means inference happening on your own machine.
Local-first AI
Running models on hardware you own, so the data never leaves it. You trade peak model quality for privacy, offline use, and no per-token bill. It is the position this lab builds from.
LoRA
Low-Rank Adaptation. A small set of extra weights trained on top of a frozen base model, so a new behaviour costs megabytes instead of a second copy of the model. Several can be swapped in and out against one base.
Quantisation
Storing weights at lower numerical precision — FP16 down to 4-bit — so a model fits in less memory and runs faster. Quality degrades gradually rather than all at once, which is exactly why it is worth measuring on your own task instead of assuming.
RAG
Retrieval-augmented generation. Fetch the relevant text first, put it in the prompt, then answer. It grounds an answer in documents you control and can update, and it is the usual alternative to fine-tuning facts into a model.
Reranking
A second pass that reorders retrieved chunks with a slower, more accurate model. Cheap retrieval finds plausible candidates; reranking decides which of them actually answers the question asked.
Temperature
A sampling knob for randomness. Low values make output repeatable and flat; high values make it varied and less reliable. When you are debugging anything else in a pipeline, set it to zero first so the model stops being a variable.
Token
The unit a model actually reads: a word, a fragment of a word, or a punctuation mark. Cost, context limits and truncation are all counted in tokens, never in characters — which is why a character count is a bad estimate of either.
Transformer
The architecture behind essentially every current language model. Its defining feature is attention; the rest is layers stacked on top of it and trained at scale.
Vector database
Storage for embeddings that answers "what is nearest to this?" quickly. The database is the easy part of retrieval. What you chose to put in it — and how you split it — decides whether retrieval works at all.

Software Engineering

Sixteen terms, in alphabetical order. These are the ones that decide how work here is built, reviewed and shipped.

API
The contract one piece of software offers another: what may be called, what must be passed, what comes back. The contract is the product; the implementation behind it is free to change as long as the contract does not.
Big-O notation
How an algorithm's cost grows as its input grows, with constant factors ignored. It answers "does this survive ten times the data", not "is this fast today" — and the two questions have different answers more often than people expect.
CI/CD
Continuous integration and continuous delivery: every push is built and tested automatically, and what passes is fit to ship. The value is that a broken change is caught by a machine on a schedule rather than by a person eventually.
Content Security Policy
A browser-enforced list of where a page is allowed to load code from. Restricted to the page's own origin, it turns an injected inline script into a no-op instead of an incident. Every page on this site ships one, this one included.
Dependency
Code you did not write but now ship and maintain. Each one is a standing bet on somebody else's release schedule, security posture and continued interest — which is why this site ships none to the browser.
Idempotence
The property of an operation that can be repeated without changing the result beyond what the first run did. It is the property that makes a retry safe, and the one missing whenever a retry causes a duplicate.
Immutability
Not modifying a value after creating it — producing a new one instead. It removes an entire class of bug in which two parts of a program disagree about the current state of the same object.
Linting
Static checks for the rules a language does not enforce: unused variables, unsafe patterns, house style. Cheap to run, and it settles style arguments before review rather than during it.
Memoisation
Caching a function's result against its arguments so repeat calls are free. Correct only for pure functions — applied to one with side effects, it does not speed the side effects up, it silently stops them happening.
Progressive enhancement
Building so the page works as plain HTML first, then layering behaviour on top. The test is whether it still works with JavaScript disabled. For this site's navigation it does: the menu is a list of real links, and the script only rearranges it.
Race condition
A bug whose outcome depends on which of two concurrent operations finishes first. It reproduces when it feels like it, which is why it is usually discovered in production rather than in a test.
Refactoring
Changing a program's structure without changing what it does. If behaviour changed, it was not a refactor — it was a change, and it needs the review a change gets.
Regression test
A test written for a bug that already shipped once, so it cannot ship twice. Often the most valuable test in a suite, because it is the only kind you know for certain was needed.
Semantic versioning
MAJOR.MINOR.PATCH, where the major number is a promise: it moves only when something you depend on breaks. Version ranges are safe exactly to the degree the publisher keeps that promise.
Static site
A site served as files, with no application server building pages per request. Nothing to exploit at request time, nothing to keep running, and nowhere for user data to accumulate. This site is one.
Technical debt
The future cost of a shortcut taken now. Legitimate when it is taken deliberately and written down with a plan to repay it. The damaging kind is the debt nobody recorded, which is discovered by the next person, under deadline.
