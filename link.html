Link

Pull every URL out of a document and get back a deduplicated list.

Nothing on this page runs yet. link is registered in the tool spec with a status of dev, which means the contract exists — argument names, types, defaults and the errors they raise — but no implementation is attached to it. The argument table below is generated from that spec, so it is the real contract rather than a sketch of one, and the code that eventually lands has to satisfy it rather than redefine it.

Why the spec comes first

A tool here is described in exactly one place. spec/manifest.json is read by the browser runtime, by the intent parser, by the assistant's capability list and by the Python package, so an argument cannot be documented on a page and rejected by the code — the page is built from the same object the validator uses. Writing the entry before the implementation means the first version of the tool is checked against a contract that already exists, instead of a contract reverse-engineered from whatever the first version happened to do.

Calling it today is not a silent no-op. The Python registry raises ToolNotFound naming the tool as declared but unimplemented, and the browser runtime has no branch for it at all. An empty result would be the dangerous outcome here: a list of no links is indistinguishable from a document that genuinely has none.
